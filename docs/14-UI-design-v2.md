# daily-health-tracker 新デザイン設計書

## 1. 目的

`daily-health-tracker` のWeb版UIを、ポートフォリオとして提示できるモダンで実用的なデザインへ刷新する。

今回の変更では、既存機能や既存データ構造を可能な限り維持し、主に以下を改善する。

* UI全体のデザイン刷新
* 入力画面の視認性・操作性向上
* 体調スコアUIの簡素化
* 履歴画面の再設計
* 週単位のグラフ表示追加
* PC・タブレット・スマートフォンへのレスポンシブ対応

大規模な機能追加やアーキテクチャ変更は目的としない。

---

# 2. 対象範囲

## 対象

* React Web版 `daily-health-tracker`
* 記録画面
* 履歴画面
* 共通ヘッダー
* レスポンシブデザイン

## 対象外

* React Native版
* ネイティブモバイルアプリ専用UI
* ロゴ制作
* DB構造の変更
* API仕様の不要な変更
* 認証方式の変更
* 大規模なコンポーネント設計変更

ロゴは後から別途検討する。

---

# 3. デザインコンセプト

健康情報を日常的に記録・確認するための、シンプルで落ち着いた健康管理Webアプリを目指す。

以下を重視する。

* 清潔感
* 視認性
* シンプルさ
* 操作の分かりやすさ
* 過度に装飾しない
* 管理画面・業務システムのような古い印象を避ける
* ポートフォリオとして見ても自然なモダンUI

派手なグラデーションや過剰なアニメーションなどは使用しない。

---

# 4. 基本デザイン

## 4.1 カラー

基本カラーは以下の方向性とする。

* ページ背景：白または非常に薄いグレー
* カード背景：白
* メインテキスト：濃いグレー
* サブテキスト：中間グレー
* border：薄いグレー
* アクセントカラー：緑
* 選択状態・保存ボタンなど：アクセントカラー

現在の「画面上部全面が濃い緑」という構成は廃止し、緑はアクセントカラーとして利用する。

健康管理アプリとして緑のブランドイメージ自体は維持する。

---

## 4.2 タイポグラフィ

既存環境で利用できるsans-serif系フォントを使用する。

デザイン変更だけを目的として、新しいWebフォント等の依存関係は追加しない。

見出し、ラベル、入力値、補助テキストで適切に文字サイズ・weightを分ける。

---

## 4.3 カード

記録画面および履歴詳細ではカードUIを利用する。

カードは以下を基本とする。

* 白背景
* 角丸
* 薄いborder
* 控えめなshadow
* 十分なpadding
* カード同士に明確な余白

shadowを強くしすぎない。

---

## 4.4 アイコン

現在使用している絵文字をデザイン上の主要アイコンとして使用しない。

既存プロジェクトにアイコンライブラリが導入済みであれば、シンプルな線画アイコンを利用してよい。

アイコンを追加するためだけに新しい大規模なUIライブラリを導入しない。

必要でなければテキストのみでもよい。

# 17. グラフの欠損データ

記録が存在しない日を `0` として扱わない。

例えば、

```text
8/10  2200
8/11  2300
8/12  データなし
8/13  2100
```

の場合、8/12は欠損値として扱う。

折れ線グラフでは、データのない部分を0まで落とさず、線を途切れさせる。

理由：

未入力と「0を記録した」は意味が異なるため。

# 31. 確定した実装方針（ディスカッション反映）

本章は、設計方針を実装へ落とす際に確定した技術選定・仕様を記載する。上位章と差異がある場合は本章を優先する。

## 31.1 追加ライブラリ

デザイン刷新に伴い追加する依存は次の2つのみとする。CSSフレームワークやUIフレームワークは追加しない。

| 用途 | ライブラリ |
| --- | --- |
| 週間折れ線グラフ | `recharts` |
| 線画アイコン | `lucide-react` |

## 31.2 日付Pickerの実現方式

既存の `react-calendar` を流用し、常設表示をやめてポップオーバー（ボタン押下で開閉）として利用する。表示は `[ 📅 YYYY / MM / DD ] [ 今日 ]` に統一する。新しい日付ライブラリは追加しない。

既存の `GET /api/history/monthly` は残し、ポップオーバー内カレンダーで記録のある日をマーカー表示するために利用する。

## 31.3 グラフ用データの取得方式

週間グラフのデータは、新設する `GET /api/history/weekly?date=YYYY-MM-DD` を1回呼び出して取得する。

* 週範囲（日曜〜土曜）の算出は**バックエンド側へ集約**する。
* 応答は選択日を含む週の7日分（各日の食事・体調・筋トレ）を返す。記録のない日は `null` とし、常に7日分を返す。
* 日次記録には全項目が含まれるため、**グラフ項目（ドロップダウン）の切り替えでは再取得しない**。
* 選択日の日別詳細も、この週データから取り出して表示し、追加リクエストを発生させない。

この変更に伴い、`03-api-design` に `GET /api/history/weekly` を追記する。既存の `GET /api/history/daily` / `monthly` / `DELETE /api/history/daily` は維持し、DB・スキーマは変更しない。

## 31.4 グラフ項目・単位の一元管理

グラフ対象10項目の「キー・表示名・単位・値のアクセサ」を単一の定義（例: `graphMetrics`）で管理し、共通グラフコンポーネントへ渡す。項目ごとの個別実装はしない。

## 31.5 日別詳細の削除導線

現行の履歴画面が持つ「選択日の記録の一括削除」機能は維持する。v2では日別詳細（3カード）付近に、控えめな削除導線と確認ダイアログとして配置する（既存機能を削除しない）。

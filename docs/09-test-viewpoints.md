# 健康管理マスター テスト観点表 v0.1

## 1. ドキュメントの目的

本ドキュメントは、健康管理マスターにおけるテスト観点を整理するための資料である。

本ドキュメントでは、以下を整理する。

* テスト全体方針
* フロントエンド観点
* バックエンド観点
* API観点
* 認証・認可観点
* データ整合性観点
* 画面/API結合観点
* E2E観点
* バリデーション・エラー観点
* 日付・タイムゾーン観点
* 初期実装で優先するテスト
* 将来課題

本ドキュメントは、フロントエンドとバックエンドを完全に分離せず、機能単位・利用者操作単位で横断的にテスト観点を整理する。

---

## 2. テスト方針

## 2.1 基本方針

健康管理マスターでは、日々の記録を安全に入力・保存・参照できることを重視する。

テストでは、以下を重点的に確認する。

* 認証済みユーザーのみが記録を操作できること
* 他ユーザーの記録を操作できないこと
* 食事・体調・筋トレ記録を日付単位で保存できること
* 同一日の保存が新規追加ではなく更新として扱われること
* 未入力値や部分入力が正しく扱われること
* 完全空保存が防止されること
* JST午前5時境界の記録日が正しく扱われること
* エラー時に入力内容が失われないこと
* 削除後に履歴表示が正しく更新されること

## 2.2 初期実装のテスト方針

初期実装では、すべてを網羅するよりも、以下を優先する。

* 主要ユースケースが壊れていないこと
* 認証・認可の基本が守られていること
* DBに不正データが保存されないこと
* 画面とAPIのつながりが正しく動くこと
* 実装変更時に壊れやすい箇所を確認できること

## 2.3 テスト対象外の扱い

初期実装では、以下は詳細なテスト対象外とする。

* UIデザインの細かい見た目
* 多言語対応
* PWA
* オフライン動作
* WebView
* React Native
* 高度なアクセシビリティ
* 負荷試験
* 大規模ユーザー同時利用
* 複雑なキャッシュ制御

## 3. テスト分類

## 3.1 テスト分類一覧

| 分類          | 内容                       | 初期優先度 |
| ----------- | ------------------------ | ----- |
| フロントエンド単体   | コンポーネント、hook、フォーム変換、日付処理 | 中     |
| バックエンド単体    | Service、DTO、Guard、User解決 | 高     |
| APIテスト      | endpoint単位の正常系・異常系       | 高     |
| 認証・認可テスト    | JWT検証、未認証、他ユーザー分離        | 高     |
| DB整合性テスト    | 一意制約、upsert、削除           | 高     |
| 画面/API結合テスト | 画面操作からAPI保存・表示まで         | 高     |
| E2Eテスト      | ログインから記録・履歴確認まで          | 中     |
| バリデーションテスト  | 入力値、空値、範囲外、文字数           | 高     |
| 日付テスト       | JST午前5時境界、未来日、過去日        | 高     |
| 回帰テスト       | 既存機能が壊れていないか             | 中     |

## 3.2 テスト実装の優先順位

初期実装では、以下の順に優先する。

```text id="test-priority"
1. バックエンド/API/DBの重要ロジック
2. 認証・認可
3. バリデーション
4. 画面とAPIの結合
5. 主要E2E
6. フロントエンド細部
```

## 14. 回帰テスト観点

## 14.1 認証変更時

| 変更内容        | 確認する観点                            |
| ----------- | --------------------------------- |
| Amplify設定変更 | ログイン、callback、token取得、ログアウト       |
| Cognito設定変更 | Hosted UI、App Client、callback URL |
| Guard変更     | 認証必須API、401、User解決                |
| Userモデル変更   | User作成、cognitoSub一意、既存User取得      |

## 14.2 API変更時

| 変更内容          | 確認する観点                    |
| ------------- | ------------------------- |
| request変更     | フロントから正しいbody/queryが送信される |
| response変更    | フォーム反映・履歴表示が壊れない          |
| status code変更 | apiClientと画面のエラー処理が壊れない   |
| endpoint変更    | API関数・画面結合が壊れない           |

## 14.3 DB変更時

| 変更内容            | 確認する観点                |
| --------------- | --------------------- |
| Prisma schema変更 | migration、既存データ、API動作 |
| 一意制約変更          | upsert、重複保存           |
| nullable変更      | 部分入力、null保存           |
| 日付型変更           | recordDateのズレ         |

## 15. 初期実装で優先するテスト

## 15.1 最優先

初期実装で最優先するテストは以下。

* 認証必須APIが未認証で呼べない
* Cognito Access TokenでAPIを呼べる
* Cognito subからUserを解決できる
* 他ユーザーの記録を操作できない
* 食事記録を新規保存できる
* 食事記録を同一日で更新できる
* 体調記録を新規保存できる
* 体調記録を同一日で更新できる
* 筋トレ記録を新規保存できる
* 筋トレ記録を同一日で更新できる
* 履歴に記録あり日付が表示される
* 日次詳細が表示される
* 日次一括削除できる
* 完全空保存できない
* 未来日保存できない
* JST午前5時境界が正しい

## 15.2 次点

余力があれば確認するテストは以下。

* 成功メッセージ表示
* 保存中disabled
* 削除中disabled
* API 500時の表示
* 通信失敗時の表示
* memo文字数上限
* うるう年
* 月末・月初の履歴表示
* ログアウト後の状態破棄
